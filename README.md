# Corporate Rating Downgrade Prediction

This repository contains the R scripts used for the empirical workflow in **Corporate Rating Downgrade Prediction: An Interpretable Multi-Horizon Statistical Learning Framework**.

The project forecasts S&P long-term issuer-rating downgrades for European listed non-financial firms across four quarterly horizons (`t+1` to `t+4`). The workflow builds a firm-quarter panel, combines firm-level, rating, macroeconomic, and systemic-risk predictors, tunes several statistical-learning models, evaluates selected specifications on a locked out-of-time test period, and produces interpretability summaries based on ALE and RGE.

## Data availability

The input data are proprietary or third-party datasets and are **not included** in this repository. The `input/` folder only documents the expected file names and layout. Generated outputs are also ignored by default to avoid committing derived data, fitted model objects, or large result files.

## Workflow scripts

Run the scripts from the repository root, or call each script directly with `Rscript`.

1. `scripts/Step_01_Build_Rating_Panel.R` builds the firm-quarter rating panel from S&P rating actions.
2. `scripts/Step_02_Build_Macro_Systemic_Dataset.R` builds country-quarter macroeconomic and systemic-risk variables.
3. `scripts/Step_03_Build_Final_Modeling_Panel.R` merges firm, rating, macro, systemic-risk, and downgrade-target data; it also creates temporal folds and the generated modelling manifest used by later steps.
4. `scripts/Step_04_Tune_Models_Expanding_Window.R` tunes logit, probit, Random Forest, XGBoost, Elastic Net, and GAM models with expanding-window validation.
5. `scripts/Step_05_Run_Locked_Test.R` refits selected configurations on the pre-test sample and evaluates them on the locked 2019Q1-2025Q4 test period.
6. `scripts/Step_06_Summarise_Model_Families.R` produces model-family locked-test benchmark summaries.
7. `scripts/Step_07_Bootstrap_Locked_Test_Stability.R` evaluates locked-test metric stability with issuer-cluster and time-block resampling.
8. `scripts/Step_08_Paired_Model_Family_Uncertainty.R` computes paired uncertainty summaries relative to logit.
9. `scripts/Step_09_ALE_RGE_Explainability.R` produces ALE and block-level RGE explainability summaries.
10. `scripts/Step_10_Sample_Descriptive_Appendix.R` creates descriptive appendix tables and figures for the final sample.

## Generated manifest

Step 03 creates `table_20_regressor_manifest.csv`, a derived workflow manifest that maps modelling specifications to their predictor sets. It is used internally by later scripts, especially Step 04 and Step 09, and is not intended to be stored in the repository. The file is ignored together with the other generated outputs; rerun Step 03 locally to recreate it.

## Main configuration options

Several computationally intensive steps can be controlled through environment variables before running the corresponding script.

- `PART4_ACTION`: `estimate`, `collect`, `partition`, `both`, or `none` for Step 04.
- `PART4_SPEC_BLOCK`: default `all`; can run specific predictor blocks.
- `PART4_SELECTION_RULES`: default runs `max_pr_auc`, `near_best_parsimony`, and `near_best_calibrated`.
- `PART5_SELECTION_RULE`: default inherits the Step 04 selection rule; the paper-ready configuration uses `near_best_calibrated`.
- `PART6_N_BOOT` and `PART6B_N_BOOT`: number of bootstrap replications for uncertainty summaries.
- `PART7_ALE_SCOPE`, `PART7_RGE_SCOPE`, and `PART7_FIGURE_MODE`: scope and plotting controls for explainability outputs.

Example:

```bash
PART5_SELECTION_RULE=near_best_calibrated Rscript scripts/Step_05_Run_Locked_Test.R
```

On Windows PowerShell:

```powershell
$env:PART5_SELECTION_RULE = "near_best_calibrated"
Rscript scripts/Step_05_Run_Locked_Test.R
```

## Reproducibility notes

- Paths are relative to the repository root.
- Input data and generated outputs are intentionally excluded from version control.
- Random seeds are set inside the modelling scripts where stochastic algorithms or resampling are used.
- Some steps are computationally intensive, especially expanding-window model tuning and bootstrap uncertainty analysis.
